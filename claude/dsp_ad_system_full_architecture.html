将设备标识映射到统一用户 ID (OneID)，并行拉取离线画像、实时画像、LBS 画像等多维特征。这是整个链路中特征准备的核心环节。

特征时效性分层 (Feature Timeliness Hierarchy)
离线特征 (T+1): Hive SQL → Spark ETL → 写入 Tair/Redis。覆盖 90%+ 基础画像，每天凌晨全量/增量更新。
近线特征 (分钟级): 用户行为日志 → Kafka → Flink 窗口聚合 (滑动/滚动窗口) → 写入 Tair。典型场景：近 30min 点击品类分布、近 1h 搜索关键词 embedding。
在线特征 (毫秒级): 在 Ad Server 内部计算，如当前时间分桶、请求来源 App、本次竞价广告数量、广告主实时消耗。不落存储，就地使用。
字节方案中使用 ByteFeature (内部特征平台) 统一管理三级特征的注册、存储和在线服务。

多路召回 (Recall / Matching)
从全量广告库 (百万~千万级) 中快速筛选出候选集 (千级)。多路并行召回，最终取并集，是保证召回率的核心。
向量召回 (ANN)
用户 embedding 与广告 embedding 做近邻检索
• 双塔模型 (DSSM) 离线训练 user/ad tower
• 用户侧: 实时 serving 或预计算
• 广告侧: 全量索引每小时更新
Faiss/Milvus TF Serving HNSW Index
Top-K: ~200 延迟 <5ms
行为召回 (Behavior)
基于用户历史行为序列触发召回
• U2I: 用户→点击/转化广告→同广告主/品类倒排
• I2I: ItemCF 协同过滤
• 行为序列 → Look-alike 人群扩散
倒排索引 Redis Sorted Set 离线 CF 计算
Top-K: ~300
定向召回 (Targeting)
广告主设定的定向条件召回
• 人群包定向 (DMP圈选)
• 基础属性定向 (地域/性别/年龄)
• 关键词/兴趣定向
• Re-targeting 重定向
倒排索引 Bitmap
精确匹配
热门/探索召回
全局热门广告 + 冷启动探索
• 全局 CTR Top-N
• 新广告冷启动池 (E&E)
• 按品类/行业热门
Redis Bandit 策略
实时意图召回
Session 级短期意图触发
• 搜索 query → 广告关键词匹配
• 近 N 次浏览商品类目
• 实时 embedding (DIEN 序列模型)
Flink ES/Faiss
召回阶段关键设计
多路并行: 各路召回独立执行并设超时 (通常 10-15ms)，结果合并去重后进入粗排。
向量召回细节: 字节使用自研 VE-KNN 引擎 (基于 HNSW + PQ 量化)；阿里使用 Proxima/Aitheta。用户 embedding 在线实时推理 (双塔 user tower 前向)，广告 embedding 离线全量构建索引。
行为召回细节: 用户近 7 天点击/转化的广告 ID → 取同广告主其他创意、同品类竞品广告、I2I 相似广告。倒排索引 key=广告属性，value=广告 ID 列表。
候选集规模: 各路合并后通常 1000~3000 条广告进入粗排。

特征拼接 & 特征工程 (Feature Assembly)
将用户特征、广告特征、上下文特征、交叉特征拼接为完整的特征向量，供排序模型使用。这一步直接决定模型效果。
用户侧特征 (User Features)
• 静态画像 (性别/年龄/设备) 离线
• 历史行为序列 (点击/转化序列 ID) 近线
• 实时行为 (本次 session 浏览序列) 在线
• 用户 embedding (双塔/预训练) 近线
• 统计特征 (7d CTR/CVR) 近线
广告侧特征 (Ad Features)
• 广告基础属性 (品类/品牌/价格) 离线
• 创意特征 (图片 embedding/文本 embedding) 离线
• 广告统计 (历史 CTR/CVR/CPC) 近线
• 广告主预算/出价 在线
• 广告质量分 近线
上下文特征 (Context Features)
• 时间特征 (小时/星期/节假日) 在线
• 设备特征 (OS/屏幕/网络) 在线
• 媒体特征 (App/广告位/场景) 在线
• 地理特征 (城市/商圈/POI) 在线
交叉特征 (Cross Features)
• 用户×广告: 历史曝光/点击次数 近线
• 用户×品类: 品类偏好度 近线
• 用户×广告主: 历史转化率 近线
• 场景×时间: 时段转化率 离线
Feature Store 架构 (字节 ByteFeature / 阿里 FeatureStore)
特征注册: 统一特征元信息管理，包括特征名、类型、来源、更新频率、Owner。
离线写入: Spark Job → Hive Table → Bulk Load → Tair/Redis (T+1 全量 + 增量)。
近线写入: Kafka → Flink → Tair/Redis (分钟级滑动窗口聚合)。
在线读取: Ad Server 批量 MGet (Tair Pipeline / Redis Cluster)，P99 延迟 < 3ms。
特征缓存: 本地 LRU Cache 缓存热 key (命中率 > 85%)，减少远端访问。

粗排 (Pre-ranking) — 千→百
用轻量模型快速筛选，从召回候选集 (~1000-3000) 中选出 Top 200-500 进入精排。核心是速度与效果的平衡。
粗排模型
• 双塔模型 (内积打分) 或浅层 DNN
• 特征交叉少，仅用核心特征
• 向量内积 + 简单 MLP 打分
• 单条推理 < 0.1ms
TF Serving Lite GPU/CPU
粗排截断策略
• 按 pCTR × bid 排序截断
• 多目标融合: α·pCTR + β·pCVR
• 保证各路召回最低配额
• 广告主多样性保障
Top 200-500

5
精排 (Fine-ranking) — 百→十
使用复杂深度模型对候选广告精细打分。这是整个链路中模型最重、特征最全的环节，直接决定广告效果。
精排模型架构
字节方案: 基于 DIN/DIEN 变体
• Attention 机制建模用户行为序列
• Multi-Task Learning (MTL): pCTR + pCVR + pLTV
• MMOE / PLE 多任务架构
• 特征交叉: DCN-V2 / AutoInt
阿里方案: DIEN → CAN → MIMN
• 长序列建模 (SIM/SDIM 千级行为)
• 多场景迁移学习 (STAR/SAMD)
TF Serving / TRT GPU P99 < 15ms
多目标预估
CTR 预估: 点击率预测，核心指标
CVR 预估: 转化率预测 (ESMM 解决样本偏差)
深度转化: 付费/次留/ROI 预估
出价校准: Isotonic Regression 校准
融合公式:
eCPM = bid × pCTR × pCVR × 1000
OCPC/OCPM 出价
精排模型 Serving 架构
模型训练: 离线全量训练 (天级) + 在线增量训练 (小时级/实时)。训练数据: Kafka → Flink → 样本拼接 → Parameter Server / GPU 集群。
模型部署: TF SavedModel → TF Serving / TensorRT 优化 → GPU 集群 (V100/A100)。
实时更新 (Online Learning): 字节使用 Monolith (自研 PS)，阿里使用 XDL/PAI。增量参数每 10-30min 推送到 Serving。
长序列优化: 用户历史行为序列可达 1000+，使用 SIM (Search-based Interest Model) 先检索 Top-K 相关行为，再做 Attention，将复杂度从 O(N) 降到 O(K)。
TF Serving / TensorRT Parameter Server Kafka Flink 样本拼接 HDFS 训练数据

重排 & 机制 (Re-ranking & Mechanism)
在精排打分基础上，叠加业务规则、预算控制、多样性、频次控制等机制约束，输出最终展示广告。
预算 Pacing
• 广告主日预算平滑消耗
• PID 控制器 + 预算分配
• 按小时粒度调节参竞率
Redis (预算计数器)
频次控制
• 用户×广告 曝光频次上限
• 用户×广告主 日频次
• 疲劳度衰减模型
Redis Bitmap/HLL
多样性 & 规则
• 同品类/广告主去重
• 竞品互斥规则
• 品牌安全 (Brand Safety)
• 政策合规过滤
竞价机制
GSP (Generalized Second Price): 传统竞价，赢者支付第二高价。
VCG: 激励兼容机制，适用于多广告位场景。
OCPC/OCPM 智能出价: 广告主设定目标 CPA，系统自动调整出价。公式: real_bid = target_CPA × pCVR × calibration_factor。
深度转化出价 (字节): 支持次留/付费/ROI 等深度目标，使用多阶段转化模型链式预估。

离线链路 (T+1 batch)
用户行为日志 → HDFS/Hive → Spark ETL → 特征 Hive 表 → Bulk Load → Tair/Redis
近线链路 (分钟级 streaming)
行为埋点 SDK → Kafka Topic → Flink (窗口聚合) → Tair/Redis
典型窗口: 滑动 30min/1h/6h，滚动 1d。聚合算子: count/sum/avg/topK/embedding_update
在线链路 (毫秒级 online)
Ad Server 请求解析 → 实时特征计算 → 直接拼入特征向量 (不落存储)
样本回流链路
曝光/点击/转化日志 → Kafka → Flink 样本拼接 → 训练样本 HDFS → 模型训练 (PS/GPU) → 模型推送 Serving
