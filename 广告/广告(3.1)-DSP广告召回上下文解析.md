# 请求准入与上下文解析

> 这一步相当于搜索和划分出我查询广告的条件，知道我有哪些参数和维度要去搜索广告

**做什么：** 当一次广告请求到达（App刷新、搜索、页面加载），广告引擎首先解析请求上下文,获取用户的各种标签和权重。 

具体内容见博客 广告(3.1)-DSP广告召回-上下文解析篇

**上下文特征大致有什么**

| 上下文类别 | 具体特征 | 注意点 |
|-----------|---------|-----------|
| 用户侧 | user_id、设备ID（IDFA/OAID/GAID）、用户画像标签、实时行为序列 | 新用户冷启动时画像缺失，需 fallback 到设备指纹或 IP 地理位置 |
| 场景侧 | 需要填充的广告位 ID（slot_id）、App/页面类型、网络制式、操作系统 | 不同广告位支持的素材格式不同，需要在召回阶段就过滤 |
| 内容侧 | 请求的广告位位于的场景，比如当前阅读的文章/视频/搜索 query（搜索广告场景） | 信息流场景要做上下文理解，搜索场景需要 query 改写与扩展 |
| 时间/地理 | 时间戳、GPS/IP 定位 | LBS 广告（本地生活、O2O）对地理精度要求高 |

**实际流程：** 请求到达时，会调用 **User Profile Service（UPS）**等系统拉取用户画像标签（年龄段、兴趣标签、消费层级、历史转化品类等），同时从 **实时特征服务** 获取用户最近 N 次点击/转化的广告 ID 序列。注意：这一步必须在 **5ms 以内** 完成。

## **用户画像标签、实时行为序列 在上下文解析中都包括哪些内容**

- 画像标签强调：描述用户的基本信息，覆盖面、稳定性、可解释，一般来自离线（T+1）+ 准实时（分钟级）融合；在线只做读取和轻量组合。用户画像是对用户中长期特征的结构化描述。在头部广告平台中，画像标签体系通常包含 6 大类、数十个子类、数万个具体标签。

- 实时序列强调：短期意图、强时效、可做频控/抑制。一般由流式系统（Kafka/Flink）实时聚合后写入 KV/FeatureStore，在线请求时一次性取回。是 "原始行为的有序列表" (具体到每一次操作)保留了 时间顺序 + 具体对象 + 行为类型，序列中蕴含了 "兴趣演化"、"意图变化"、"行为模式"

##### - 权重计算公式  基于时间衰减的频次加权

离线+实时计算 (spark,flink)

```
W(tag) = Σ [ action_weight × freq × time_decay × context_boost ]

```

- action_weight（行为类型权重）
不同行为代表的兴趣强度天然不同。以信息流广告为例，一个典型的权重表：

###### **action** 如何确定 整体分为几个流程

1. **第一阶段:冷启动阶段** 
靠业务直觉先拍一版,比如点击点击:1.0深度阅读:2.0收藏:3.0购买:10.0
2. **第二阶段:数据回归校准**
系统跑起来有数据之后，就用数据来反推每个行为到底值多少分。核心思路是：看某个行为发生后，对后续转化的提升有多大。

**这里主要有两种方法**

1. 方法一：条件转化率反推
统计每种行为发生后，用户对同标签广告的后续点击率/转化率提升倍数：
```
-- 简化的SQL逻辑
-- 基准：全体用户对"健身"标签广告的平均点击率
base_ctr = 0.02  (2%)

-- 做过不同行为的用户，对"健身"广告的点击率
曝光未点击过健身内容的用户 → ctr = 0.018  → 提升倍数 0.9
点击过健身内容的用户       → ctr = 0.035  → 提升倍数 1.75
收藏过健身内容的用户       → ctr = 0.058  → 提升倍数 2.9
购买过健身商品的用户       → ctr = 0.12   → 提升倍数 6.0
```
sql 逻辑

```sql
-- 统计"加购行为"发生后，同品类广告点击率的提升
WITH action_users AS (
    -- 发生过加购行为的用户及其加购品类
    SELECT user_id, category_id, action_time
    FROM user_behavior_log
    WHERE action_type = 'add_cart'
      AND dt BETWEEN '2024-01-01' AND '2024-01-31'
),
subsequent_ad_clicks AS (
    -- 这些用户后续72小时内对同品类广告的点击
    SELECT a.user_id, a.category_id,
           COUNT(DISTINCT c.click_id) AS click_cnt,
           COUNT(DISTINCT i.impression_id) AS imp_cnt
    FROM action_users a
    LEFT JOIN ad_impression_log i
        ON a.user_id = i.user_id 
        AND i.category_id = a.category_id
        AND i.imp_time BETWEEN a.action_time 
            AND a.action_time + INTERVAL 72 HOUR
    LEFT JOIN ad_click_log c
        ON i.impression_id = c.impression_id
    GROUP BY a.user_id, a.category_id
),
baseline AS (
    -- 全体用户同品类广告的平均CTR（基线）
    SELECT category_id,
           SUM(is_click) * 1.0 / COUNT(*) AS base_ctr
    FROM ad_impression_log
    WHERE dt BETWEEN '2024-01-01' AND '2024-01-31'
    GROUP BY category_id
)
SELECT 
    '加购' AS action_type,
    AVG(s.click_cnt * 1.0 / NULLIF(s.imp_cnt, 0)) AS action_ctr,
    AVG(b.base_ctr) AS base_ctr,
    AVG(s.click_cnt * 1.0 / NULLIF(s.imp_cnt, 0)) / AVG(b.base_ctr) AS lift
FROM subsequent_ad_clicks s
JOIN baseline b ON s.category_id = b.category_id;

-- 对每种action_type都跑一遍，得到lift表
```

```python
从离线数据中统计：发生某行为后，用户在未来X小时内
对相关广告产生转化（点击/下单）的条件概率
"""

# 真实数据示例（某电商广告平台统计）
# 统计口径：用户发生行为A后，72小时内对同品类广告的点击率提升倍数

action_conversion_lift = {
    'search_query':      8.5,   # 搜索后点击同品类广告的概率提升8.5倍
    'purchase':          5.2,   # 买过之后对同品类广告仍有较高点击（复购/配件）
    'add_cart':          6.8,   # 加购是非常强的意图信号
    'add_favorite':      4.1,   # 收藏
    'product_detail_view_long': 3.2,  # 详情页停留>15s
    'product_detail_view_short': 1.5, # 详情页停留<5s
    'click_ad':          2.1,   # 点击过广告
    'category_browse':   1.3,   # 浏览品类页
    'impression_no_click': 0.3, # 曝光未点击（负信号）
}

# 归一化到 [0, 1] 区间
max_lift = max(action_conversion_lift.values())
action_weights = {
    action: round(lift / max_lift, 2) 
    for action, lift in action_conversion_lift.items()
}

# 结果：
# search_query:              1.00
# add_cart:                   0.80
# purchase:                   0.61
# add_favorite:               0.48
# product_detail_view_long:   0.38
# click_ad:                   0.25
# product_detail_view_short:  0.18
# category_browse:            0.15
# impression_no_click:        0.04
```

这就是数据告诉你的真实权重，跟拍脑袋差异可能很大。比如你可能直觉觉得购买应该是点击的 10 倍，但真实的数据报告可能只有 3.4 倍——因为买完的人可能短期内不会再买同类东西了。所以这种方法也会有偏差


2. 方法二：逻辑回归学权重
把各种行为作为特征，用户是否点击/转化广告作为 label，跑一个逻辑回归：
```python
"""
用逻辑回归学习各行为类型对转化的贡献度
本质是把action_type作为特征，转化作为label
学出来的系数就是权重的参考值
"""

import numpy as np
from sklearn.linear_model import LogisticRegression

# 样本构造：每条样本是一个(user, tag)对
# 特征是该用户对该tag的各类行为计数
# label是该用户后续是否点击/转化了该tag相关的广告

# X的每一列：
# [购买次数, 加购次数, 收藏次数, 点击次数, 详情页浏览次数, 曝光次数]
X = np.array([
    [1, 0, 0, 2, 3, 10],  # 用户A对tag"运动鞋"
    [0, 1, 1, 3, 2, 8],   # 用户B对tag"运动鞋"
    [0, 0, 0, 1, 0, 5],   # 用户C对tag"手机壳"
    # ... 数百万条样本
])

y = np.array([1, 1, 0, ...])  # 是否后续转化

model = LogisticRegression()
model.fit(X, y)

# 学出来的系数：
print(dict(zip(
    ['purchase', 'add_cart', 'favorite', 'click', 'detail_view', 'impression'],
    model.coef_[0]
)))

# 示例输出：
# purchase:     0.82
# add_cart:     0.91
# favorite:     0.43
# click:        0.31
# detail_view:  0.27
# impression:   0.05

# 这个结果作为"参考值"，最终还是人工review后配置
```
这个方法的好处是模型自动学出了各行为之间的相对重要性，而且考虑了行为之间的共线性。

3. **第三阶段：分场景差异化**
跑出数据后你会发现一个重要的事实：**不同品类/场景下，同一个行为的权重完全不同。**
```
电商-快消品（零食、日用品）：
  点击: 1.0  收藏: 1.5  购买: 2.0   ← 购买权重低，因为买完很快会复购

电商-3C数码（手机、电脑）：
  点击: 1.0  收藏: 4.0  购买: 1.2   ← 收藏权重极高，因为用户会长期比价
                                       购买反而低，因为买完就不看了
信息流-新闻资讯：
  点击: 1.0  深度阅读: 5.0  分享: 8.0  ← 阅读和分享才是强信号
短视频广告：
  完播: 1.0  重复观看: 3.0  评论: 4.0  分享: 6.0
```
所以会**按业务线分别训练一套 action_weight**，不会全局共用。

> **把上面三个阶段串起来，流程是这样的：**
>
>  1. 冷启动 → 人工拍一版，先跑起来
>  2. 积累1-2周数据 → 用条件转化率反推，粗调一版
>  3. 积累1-2个月数据 → 用LR/GBDT学权重，精调
>  4. 持续运行 → 每周/每月用最新数据重新跑一次回归，更新权重
>  5. 按品类/场景 → 拆分成多套权重体系


###### **time_decay(Δt_i)** 中的 exp(-λ × Δt_i) λ 和 Δt_i 如何确定呢？

1. **Δt_i：直接算，没什么悬念**

就是第 i 次行为发生的时间到当前时刻的时间差，从日志里直接减出来：

```
Δt_i = now - action_timestamp_i
```

唯一需要确定的是**时间单位**，这取决于业务节奏：

- 短视频/信息流：用**小时**，因为兴趣以小时为粒度变化
- 电商：用**天**，购物意图持续数天
- 房产/汽车：用**周**，决策周期很长

单位选错会导致 λ 的数值不好调。比如电商场景你用秒做单位，Δt 动辄几十万，λ 就得设成 0.000001 这种极小值，容易出精度问题。 ???

2. **λ：核心超参数，三种确定方法**

1. 方法一：从业务半衰期反推

λ 和半衰期（half_life）的数学关系是确定的：
```
half_life = ln(2) / λ
即：λ = ln(2) / half_life ≈ 0.693 / half_life
```
半衰期的含义是：**一个行为的兴趣信号衰减到一半所需的时间**。这个值可以靠业务直觉先拍一版：


短视频信息流:  half_life = 4小时   → λ = 0.693/4  = 0.173  (按小时)
电商快消品:    half_life = 3天     → λ = 0.693/3  = 0.231  (按天)
电商3C数码:    half_life = 7天     → λ = 0.693/7  = 0.099  (按天)
房产汽车:      half_life = 21天    → λ = 0.693/21 = 0.033  (按天)

2. 方法二：网格搜索 + 离线评估（生产环境主流做法）
